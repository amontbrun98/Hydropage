PROBLEM IDENTIFIED:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Gunicorn was binding to port 8080 instead of Railway's $PORT variable.

Root Cause:
- Nixpacks auto-detection was ignoring $PORT
- railway.json startCommand was being overridden
- No nixpacks.toml configuration file existed

Evidence from logs:
  [INFO] Listening at: http://0.0.0.0:8080 (1)  ← WRONG!
  [INFO] Handling signal: term
  [INFO] Shutting down: Master

SOLUTION IMPLEMENTED:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Created nixpacks.toml with explicit PORT binding configuration.

Files Changed:
  ✓ api/nixpacks.toml       (NEW)      - Primary fix
  ✓ api/Procfile            (UPDATED)  - Backup start command
  ✓ api/railway.json        (UPDATED)  - Removed conflicting startCommand

KEY FILE: nixpacks.toml
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[phases.setup]
nixPkgs = ["python39"]

[phases.install]
cmds = ["pip install -r requirements.txt"]

[start]
cmd = "gunicorn app:app --bind 0.0.0.0:$PORT --workers 2 --timeout 120"
      └──────────────────────────────┬─────────────────────────────────┘
                                     │
                    This line forces gunicorn to use Railway's $PORT

HOW IT WORKS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. Railway assigns dynamic port    → $PORT=34567 (example)
2. Nixpacks reads nixpacks.toml     → Sees start command with $PORT
3. Gunicorn binds to 0.0.0.0:34567  → Uses Railway's assigned port
4. Railway proxies requests         → https://... → http://0.0.0.0:34567
5. API responds successfully        → ✓ No more 502 errors!

BEFORE vs AFTER:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
BEFORE (Broken):
  Railway    →  $PORT=34567
  Nixpacks   →  Ignores $PORT, uses default
  Gunicorn   →  Binds to 0.0.0.0:8080
  Result     →  502 Error (port mismatch)

AFTER (Fixed):
  Railway    →  $PORT=34567
  Nixpacks   →  Reads nixpacks.toml, uses $PORT
  Gunicorn   →  Binds to 0.0.0.0:34567
  Result     →  ✓ Success!

WHY THIS FIX WORKS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Nixpacks Priority Order:
  1. nixpacks.toml          ← Highest priority (we added this!)
  2. Procfile               ← Fallback
  3. Auto-detection         ← Was using this (broken)
  4. railway.json           ← Often ignored with Nixpacks

By creating nixpacks.toml, we force Nixpacks to use our explicit start command
with $PORT variable binding, bypassing the broken auto-detection.

Port Assignment:

  - Port changes between deployments (that's why $PORT is needed)
